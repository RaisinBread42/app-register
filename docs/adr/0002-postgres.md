# ADR 0002 — Postgres only, PGlite for unit tests

**Status:** Accepted
**Date:** 2026-11-22
**Supersedes:** the Persistence row of [ADR 0001](0001-stack.md)

## Context

Issue [02] stored apps in SQLite. Issue [10] adds the full MVP schema with workspaces, composite foreign keys, partial unique indexes and CHECKs built from shared constants. Running SQLite in dev and Postgres in production would mean two dialects, two migration sets and bugs that only show up in one of them.

## Decision

| Where | Database | Driver |
| --- | --- | --- |
| Local dev | Postgres 18 in Docker (`docker-compose.yml`) | `postgres` (postgres.js) + `drizzle-orm/postgres-js` |
| CI | `postgres:18` service container, migrations applied twice | same |
| UAT / PROD | Postgres 18 via `DATABASE_URL` | same |
| Unit tests | PGlite in-process, in-memory, a fresh DB per test from the real `drizzle/` migrations | `@electric-sql/pglite` + `drizzle-orm/pglite` |

- One schema (`src/lib/db/schema.ts`), one migration history (`drizzle/`, generated by drizzle-kit, applied by Drizzle's migrator via `npm run db:migrate`). Each migration has a hand-written inverse in `drizzle/rollback/`.
- SQLite (`better-sqlite3`) and the `CREATE TABLE IF NOT EXISTS` bootstrap are removed.
- Primary keys are UUIDs from `newId()` in app code, not DB defaults, so PGlite and Postgres behave the same.
- Allowed values are `text` + `CHECK` from `src/lib/constants.ts`, not Postgres `ENUM`s (adding a value is a one-line constant change plus a generated migration; no `ALTER TYPE`).

## Why PGlite for unit tests

- Real Postgres semantics (constraints, partial indexes, `IS DISTINCT FROM`, `timestamptz`) without Docker, so `npm test` and the gate run anywhere, offline and fast.
- Tests run the same migrations production runs, so a broken migration fails the unit tests.

## Trade-offs

- PGlite 0.4.6 ships **Postgres 17.5**, production runs **18**. Our schema uses nothing 18-specific; CI applying the migrations to a real `postgres:18` closes the gap. Revisit if we adopt an 18-only feature.
- A fresh PGlite per test costs ~1.5 s. Fine at the current test count; if the suite grows, snapshot a migrated data dir once per run.
- Developers need Docker to run the app locally (not to run tests).
